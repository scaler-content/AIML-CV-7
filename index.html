01

From “what” to “where”

SafeSight, a visual inspection system, receives an image and must answer two different questions: what is present? and where is each object? Embeddings (the previous topic) are great for “find images like this one”, but they do not give the coordinates of any object. Localization adds a location to a class prediction, and detection extends this to many objects.

If a model returns only “animal” for a photo with a dog and a cat, what is missing for an application that must count each animal? The individual instances, their classes, and their locations.

02

Bounding boxes and dataset design

Two common representations: (x_min, y_min, x_max, y_max) (top-left and bottom-right corners) and (x_center, y_center, width, height). Always check the dataset's convention before training. For an image of width W and height H, valid pixel coordinates satisfy 0 ≤ x_min < x_max ≤ W and 0 ≤ y_min < y_max ≤ H.

Dataset exploration checklist

The method applies to any detection dataset, including a safety-critical one such as weapon detection. A model is not safe or reliable merely because it trains: a dataset-specific detector needs a separately reviewed dataset, annotation policy and deployment safeguards.

03

Building an object-localization model

A pretrained ResNet101 is the feature extractor. Its final classification layer is replaced by two task-specific heads: a classification head (target class) and a regression head (four box coordinates). The model learns two related but different tasks.

Visualizer · The two-head localizer

Each training example needs an image tensor, a class label, a target box, a consistent coordinate convention and a train/validation/test split. Geometric augmentations must transform the box too: if an image is flipped horizontally, the box must be flipped as well.

Why predict centre and size, not four corners?

Four independent sigmoid outputs lie in [0, 1] but do not guarantee x_min ≤ x_max or y_min ≤ y_max. The teaching head predicts normalized (centre_x, centre_y, width, height) and converts to clipped corners, which guarantees ordered corners. (A production detector uses its own box parameterization and decoding; this is a clear single-target example, not Faster R-CNN's internal head.)

Visualizer · Four sigmoid outputs, two ways to read them

The training objective

L_total = L_classification + λ × L_box

λ balances the two loss scales. Classification uses cross-entropy; box regression can use Smooth L1. The recorded illustration uses two images, three classes, and λ = 1.

Visualizer · Loss for a toy batch

Logits [[2.0, 0.4, −0.2], [0.1, 1.8, 0.3]] with targets [0, 1]; predicted boxes [[.1,.2,.7,.8],[.2,.1,.8,.9]] vs. targets [[.12,.18,.68,.82],[.22,.12,.78,.88]]. The values are recomputed live from these tensors: cross-entropy 0.3064, box loss 0.0002.

Notice how small the box loss is next to the classification loss: this is exactly why λ exists. Actual training must also mask invalid or missing boxes and make sure the target box format matches the model output.

Scope

The notebook defines this architecture and its output format but includes no labelled localization dataset, so it does not claim to train or validate a custom ResNet101 localizer, and no localization accuracy is reported here.

Code: the model 
class ResNet101Localizer(nn.Module):
    def __init__(self, num_classes):
        super().__init__()
        backbone = resnet101(weights=ResNet101_Weights.DEFAULT)
        in_features = backbone.fc.in_features
        backbone.fc = nn.Identity()
        self.backbone = backbone
        self.classifier = nn.Linear(in_features, num_classes)
        self.box_regressor = nn.Sequential(nn.Linear(in_features, 256), nn.ReLU(), nn.Linear(256, 4), nn.Sigmoid())
    def forward(self, images):
        features = self.backbone(images)
        class_logits = self.classifier(features)
        cx, cy, width, height = self.box_regressor(features).unbind(dim=1)
        x1 = (cx - width / 2).clamp(0, 1); y1 = (cy - height / 2).clamp(0, 1)
        x2 = (cx + width / 2).clamp(0, 1); y2 = (cy + height / 2).clamp(0, 1)
        return class_logits, torch.stack((x1, y1, x2, y2), dim=1)

04

Evaluating localization: Intersection over Union

A model can predict the correct class but place the box poorly, so classification metrics alone are insufficient.

IoU = Area(predicted ∩ ground truth) / Area(predicted ∪ ground truth)

0 means no overlap, 1 means perfect overlap; larger means better alignment.

Visualizer · Move the predicted box

Ground truth is fixed at (10, 10, 60, 60). The default prediction (20, 20, 70, 70) gives the lecture's 0.471.

Visualizer · Mean box IoU

Compute IoU for every evaluated image that has a ground-truth box, then average. Edit the per-image IoUs (illustrative).

Say which “mIoU” you mean

Report this average as mean box IoU. Object-detection mAP matches predicted detections to ground-truth objects across confidence thresholds and is a different metric. For semantic segmentation, “mIoU” usually means class-wise pixel IoU averaged over classes. State the definition whenever you report a metric.

Code and output 
def box_iou(box_a, box_b):               # each box: (x1, y1, x2, y2)
    ax1, ay1, ax2, ay2 = box_a; bx1, by1, bx2, by2 = box_b
    ix1, iy1 = max(ax1, bx1), max(ay1, by1); ix2, iy2 = min(ax2, bx2), min(ay2, by2)
    intersection = max(0.0, ix2 - ix1) * max(0.0, iy2 - iy1)
    area_a = max(0.0, ax2 - ax1) * max(0.0, ay2 - ay1); area_b = max(0.0, bx2 - bx1) * max(0.0, by2 - by1)
    union = area_a + area_b - intersection
    return intersection / union if union > 0 else 0.0

05

From one object to many: sliding windows and NMS

A single-target localizer predicts one box, but a real image can contain many objects, so we need to propose and evaluate multiple candidate regions. Sliding window: place a window, classify the crop or score it for an object, move across the image, and repeat at multiple window sizes.

Visualizer · Why sliding windows are expensive

Illustrative numbers. Per scale: windows = ((W − w)/stride + 1) × ((H − w)/stride + 1) for a square window; scales are assumed at 1×, 1.5×, 2×, … of the base window for the count. Most windows contain background, objects may not match the chosen shapes, and one object is hit by many overlapping windows.

Non-Maximum Suppression

  1. Sort candidate boxes by confidence score.
  2. Keep the highest-scoring box.
  3. Compare it with the remaining boxes using IoU.
  4. Suppress boxes whose overlap exceeds the NMS threshold.
  5. Repeat.

Visualizer · NMS and two different thresholds

The lecture's toy boxes: scores 0.95 and 0.88 strongly overlap, 0.72 is separate.

Do not mix up the thresholds

Confidence threshold removes low-score predictions. NMS IoU threshold removes overlapping duplicates. NMS does not simply keep one box per image: it suppresses sufficiently overlapping candidates, typically within a class.

Code and output 
example_boxes = torch.tensor([[10.,10.,100.,100.], [15.,15.,98.,98.], [120.,20.,200.,100.]])
example_scores = torch.tensor([0.95, 0.88, 0.72])
for iou_threshold in (0.3, 0.7):
    kept = nms(example_boxes, example_scores, iou_threshold)

R-CNN

R-CNN (Region-based Convolutional Neural Network) uses region proposals to decide which parts of an image deserve classification.

Visualizer · The original R-CNN pipeline

Main limitation: running the CNN separately for many proposals is computationally expensive and repeats feature extraction for overlapping regions; training also has multiple stages. Fast R-CNN fixes the repeated work:

Counts of backbone passes only (R-CNN: one per proposal; Fast R-CNN: one for the whole image). The proposal count is illustrative, and per-pass cost differs, since R-CNN's passes are on small warped crops.

07

Fast R-CNN

  1. Run the full image through a CNN backbone once.
  2. Get region proposals (e.g. Selective Search).
  3. Map each proposal onto the shared feature map.
  4. Apply ROI Pooling to get a fixed-size representation.
  5. Task-specific heads output class probabilities and box refinement.

Proposals differ in size but fully connected layers expect a fixed-size input, so ROI Pooling converts each region to a fixed spatial size.

Visualizer · ROI Pooling to a fixed 2 × 2

An 8 × 8 feature map (illustrative values). Choose a region of any size: it is split into a 2 × 2 grid of bins and max-pooled in each.

Fixed-size output

What Fast R-CNN does not solve: it still depends on an external proposal method such as Selective Search, which remains a separate bottleneck.

ROI Pooling vs. ROI Align

The original Fast R-CNN paper introduced ROI Pooling. Modern TorchVision Faster R-CNN ResNet-FPN models use MultiScaleRoIAlign, an ROI Align-style operator. Both give fixed-size region features, but ROI Align avoids the coordinate quantization of classic ROI Pooling, so do not call the TorchVision operator classic ROI Pooling.

08

Faster R-CNN

Faster R-CNN removes the external proposal bottleneck with a Region Proposal Network (RPN) that shares convolutional features with the detection network.

Visualizer · Two-stage pipeline

Anchors and the RPN

At each feature-map location, the RPN considers several anchor boxes (reference boxes with different scales and aspect ratios). For each it predicts objectness (does this anchor likely contain an object?) and box offsets (how to move and resize it to fit better). The proposals are then filtered and passed to the detection head.

Visualizer · Anchors at one location

Illustrative sizes. Choose scales and aspect ratios; anchors are drawn at a chosen feature-map location.

Combined losses

  • RPN box regression loss
